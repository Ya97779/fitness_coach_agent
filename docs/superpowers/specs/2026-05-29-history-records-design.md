# 历史记录页面设计

> 日期: 2026-05-29
> 范围: 小程序首页"历史趋势"改为"历史记录"，改造 stats 页面

## 背景

当前首页"历史趋势"按钮只是跳转到统计图表页（`pages/stats/stats`），用户无法查看往日的饮食和运动记录。需要将其改造为一个集历史记录查看和统计图表于一体的页面，并加入本地缓存提升体验。

## 改动范围

| 文件 | 改动 |
|------|------|
| `pages/home/home.wxml` | 按钮文案 "历史趋势" → "历史记录" |
| `pages/stats/stats.wxml` | 新增 Tab 切换 + 日历 + 记录列表 |
| `pages/stats/stats.js` | 新增历史记录数据加载、缓存、日历逻辑 |
| `pages/stats/stats.wxss` | 新增 Tab、日历、记录卡片样式 |
| `pages/stats/stats.json` | 注册日历组件 |

## 页面结构

```
┌──────────────────────────┐
│  ← 历史记录               │
├──────────────────────────┤
│  [ 历史记录 ]  [ 统计图表 ] │
├──────────────────────────┤
│                          │
│  (Tab 1: 日历 + 记录列表)  │
│  (Tab 2: 折线图)          │
│                          │
└──────────────────────────┘
```

## Tab 1：历史记录

### 日历组件

- 自定义实现的月历（不引入第三方依赖），在 stats.wxml 中内联
- 显示当前月份的完整日历网格（7列 × 5-6行）
- 左右箭头切换月份
- 有记录的日期下方显示圆点标记
- 默认选中今天
- 点击某天，记录列表滚动到对应日期

### 记录列表

- 按日期倒序分组（最近在上）
- 每天一个卡片：
  - 日期标题：`5月29日 周四`
  - 汇总行：`摄入 xxx kcal · 消耗 xxx kcal`
  - 饮食记录：按餐次分组（早餐/午餐/晚餐/加餐），每条 `食物名  xxx kcal`
  - 运动记录：每条 `运动名  时长  xxx kcal`
- 仅查看，不支持编辑/删除
- 无限滚动加载：每次加载 7 天，触底加载更多

## Tab 2：统计图表

### 折线图：每日净热量趋势

- 单条折线显示每日净热量（摄入 - 消耗）
- 零线处绘制虚线
- 零线上方区域填充盈余色（红色/橙色系）
- 零线下方区域填充缺口色（绿色系）
- 不显示具体数值标签，只看趋势走向
- X 轴显示日期（MM-DD），保留"近 7 天"/"近 30 天"切换
- 使用微信原生 Canvas API（与现有图表一致），在 `pages/stats/stats.wxml` 中用 `<canvas>` 绘制

### 相比现有图表的改动

- 移除现有的双线折线图（摄入 vs 消耗）和柱状图
- 替换为单线净热量趋势图 + 区域填充
- 移除所有数值标签

## 本地缓存策略

参考聊天页面（`pages/chat/chat.js`）的缓存模式。

### 数据流

```
页面加载
  ├─ 有缓存？→ 立即渲染缓存数据
  │            → 后台请求 GET /api/v1/user/me/logs
  │            → 数据有变化？→ 更新缓存 + 重新渲染
  └─ 无缓存？→ 显示 loading
              → 请求服务端 → 渲染 + 写入缓存
```

### 缓存细节

| 项 | 值 |
|----|-----|
| 缓存 key | `history_logs` |
| 缓存内容 | DailyLog 列表（含嵌套 food_items、exercise_items） |
| 缓存大小 | 保留最近 90 天（约 100-200KB，远低于 1MB 上限） |
| 写入时机 | 服务端返回后；用户新增记录后增量更新当天 |
| 过期策略 | 每次打开页面后台同步，优先显示缓存 |

### 日历圆点数据

从缓存的 logs 中提取有记录的日期集合，无需额外 API。

## 后端影响

- 无新增 API，复用现有 `GET /api/v1/user/me/logs`
- 无数据库变更

## 首页改动

- `home.wxml` 第 57 行：`历史趋势` → `历史记录`
- 图标从 `~` 改为日历或列表相关图标
- `goStats()` 方法和跳转路径不变
