前端层
用户界面与交互入口
输入 用户操作
  • 文本消息输入
  • 登录授权（微信 code）
  • 表单数据填写（身体数据、饮食偏好）
  • 快捷记录操作（食物/运动）
处理 前端逻辑
  • JWT Token 存储与管理
  • SSE 流式响应渲染
  • Markdown 解析与显示
  • 意图检测按钮渲染
输出 API 请求
  • POST /api/v1/auth/wx-login
  • POST /api/v1/chat/stream
  • GET /api/v1/user/me
  • POST /api/v1/food-log
  • POST /api/v1/exercise-log
前端实现细节
1
微信小程序
原生微信小程序，使用 wx.request 发起 HTTP 请求
技术栈：微信原生框架 通信方式：wx.request + SSE 流式 存储：wx.setStorageSync (Token) 渲染：mp-html 组件渲染 Markdown
2
Streamlit Web
Python 单文件应用，使用 requests 库调用后端 API
技术栈：Streamlit + Plotly 通信方式：requests + SSE 流式 存储：st.session_state 渲染：原生 Markdown 支持
3
SSE 流式响应
Server-Sent Events 实现实时流式输出
事件类型： - data: 文本内容块 - status: 状态消息 - intent: 意图检测结果 - queue: LLM 排队状态 - [DONE]: 流结束标记
🔌
API 层
FastAPI 路由与中间件
输入 HTTP 请求
  • 请求体（JSON）
  • Authorization: Bearer JWT
  • 路径参数、查询参数
处理 中间件链
  • CORS 跨域处理
  • JWT 鉴权验证
  • 限流保护（60/min）
  • 全局异常处理
输出 响应格式
  • JSON 响应（同步）
  • SSE 事件流（流式）
  • HTTP 状态码
  • 错误信息
核心 API 端点
1
POST /api/v1/auth/wx-login
微信登录，返回 JWT Token
输入：{"code": "wx_auth_code"} 处理：code → openid → 查找/创建用户 → 生成 JWT 输出：{"token": "jwt_token", "user": {...}}
2
POST /api/v1/chat/stream
SSE 流式对话端点
输入：{"message": "用户问题"} 处理：加载记忆 → 路由分析 → Agent 处理 → 流式输出 输出：SSE 事件流（data/status/intent/queue）
3
POST /api/v1/food-log
食物记录，支持 LLM 热量估算
输入：{"name": "苹果", "meal_type": "snack"} 处理：查缓存 → LLM 估算 → 记录 → 更新统计 输出：{"id": 1, "calories": 95, "estimating": false}
4
POST /api/v1/exercise-log
运动记录，支持 MET 公式计算
输入：{"type": "跑步", "duration": 30} 处理：MET 公式 / LLM 估算 → 记录 → 更新统计 输出：{"id": 1, "calories": 250, ...}
🤖
Agent 层
LangGraph 多 Agent 编排系统
输入 AgentState
messages: List[Message] user_id: int user_profile: Dict daily_stats: Dict memory_summary: Dict enhanced_prompts: Dict[str, str]
处理 工作流节点
  • router: 意图识别与路由
  • chat: 闲聊处理（无工具）
  • nutrition: 营养师（5 工具）
  • fitness: 健身教练（4 工具）
  • expert_review: 专家评审
输出 处理结果
response: "AI 回复内容" agent: "nutrition" expert_review: { score: 4, approved: true, retries: 0 } intent: Dict (可选)
LangGraph 工作流
1
Router 路由
混合路由策略：关键词预筛 + LLM 兜底
关键词匹配：40+ 中文关键词快速分类 LLM 确认：模糊场景调用 LLM 二次确认 输出：chat / nutrition / fitness
2
Agent 处理
根据路由结果调用对应 Agent
闲聊 Agent：直接 LLM 对话，无工具 营养师：查用户信息、记录食物、查统计、搜 API、搜 RAG 健身教练：查用户信息、记录运动、估算热量、搜 RAG
3
专家评审
1-5 分评分，<3 分重试，最多 3 次
评分维度：专业性、个性化、实用性、安全性 快速通道：简单事实查询跳过评审 重试机制：评分 <3 时重新生成
4
记忆注入
将用户上下文注入 System Prompt
注入内容： - 用户画像（身高、体重、目标等） - 当日统计（摄入、消耗） - 本周统计（趋势、平均值） - 近期对话历史
📚
RAG 层
检索增强生成系统
输入 检索请求
  • 查询文本
  • top_k 返回数量
  • 检索模式（hybrid/vector/bm25）
处理 检索流程
  • 文档加载（PDF/DOCX/TXT/MD）
  • 智能分块（500 字/块）
  • 向量化（Embedding-2）
  • 混合检索（向量 + BM25）
  • RRF 融合排序
输出 检索结果
[{ content: "文档片段", metadata: {source: "file.pdf"}, score: 0.85 }]
RAG 高级功能
1
混合检索
向量语义检索 + BM25 关键词检索，RRF 融合
向量检索：ChromaDB + Embedding-2 语义相似度 BM25：jieba 分词 + 关键词匹配 RRF 融合：Reciprocal Rank Fusion 排序 权重配置：vector_weight=0.5, bm25_weight=0.5
2
Query Expansion
LLM 生成多个相关查询，扩大召回
输入："增肌饮食" 扩展：["高蛋白食物", "健身餐单", "蛋白质摄入量"] 每个扩展查询独立检索，结果去重合并
3
HyDE
假设性文档嵌入，提升检索相关性
流程：用户问题 → LLM 生成假设性文档 → 向量检索 原理：假设性文档更接近知识库文档的表述方式 结合：HyDE 结果与原始查询结果混合排序
4
Self-RAG
自我反思纠正，提升回答质量
流程：检索 → 生成 → 反思 → 纠正 反思维度：相关性、完整性、准确性 输出：包含反思标记的回答
5
增量索引
启动时自动检测新文档，增量更新索引
检测：MD5 对比，识别新增/更新/删除文件 新增：直接添加到向量库 更新：触发全量重建 删除：从向量库清除
💾
数据层
数据模型与持久化
输入 写入操作
  • 用户创建/更新
  • 饮食记录
  • 运动记录
  • 对话日志
  • 热量缓存
处理 ORM 映射
  • SQLAlchemy ORM
  • 关系映射
  • 事务管理
  • 连接池
输出 查询结果
  • 用户画像
  • 每日统计
  • 每周趋势
  • 对话历史
数据模型关系
1
User 用户表
存储用户基本信息和身体数据
字段： - id, openid, nickname, avatar_url - height, weight, age, gender - target_weight, goal - bmr, tdee - allergies, training_preference, dietary_preference 关系：1:N → DailyLog, ConversationLog
2
DailyLog 日志表
每日饮食运动记录汇总
字段： - id, user_id, date - intake_calories, burn_calories - weight_log, notes 关系：N:1 → User, 1:N → FoodItem, ExerciseItem
3
FoodItem 食物表
具体食物记录
字段： - id, log_id, name, calories - meal_type (breakfast/lunch/dinner/snack) - portion_qty, portion_unit 关系：N:1 → DailyLog
4
ExerciseItem 运动表
具体运动记录
字段： - id, log_id, type, name - sets, reps, weight - duration, calories 关系：N:1 → DailyLog
5
ExerciseCalorie 热量表
运动热量参考数据（LLM 缓存）
字段： - id, name (unique) - calories_per_set - category, aliases (JSON) 用途：缓存 LLM 估算的运动热量
6
ConversationLog 对话表
对话历史记录
字段： - id, user_id, session_id - agent_type (chat/nutrition/fitness) - user_message, agent_response - created_at 用途：对话历史、上下文记忆
